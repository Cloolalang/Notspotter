4. ConnectivityStats built in three places
   Nearly the same radio -> stats mapping exists in:
   - CellularPassiveSignalMonitor
   - CellularPingMonitor.emitStats
   - MonitorState.applyIdleSignalMetrics
   A shared factory like CellularRadioMetrics.toMonitoringStats(...) would reduce
   drift when fields are added.

5. Four copy-paste periodic announcement loops
   ConnectivityMonitorService has nearly identical logic for no-signal, 2G,
   limited service, and dead zone (start/stop job, 30s loop, condition check).
   One small helper would cut ~80 lines and keep behaviour consistent.

6. Duplicate duration sliders in UI
   AudioVolumeSettingsCard.DurationSlider and

   Could be one shared composable in e.g. ui/components/DurationSlider.kt.

   - signalPulseDurationMs param in DeadzoneTierSettings — unused (tier 9 uses
     deadzoneTierPulseDurationMs)
   - Deprecated const aliases in SignalStrengthAudio.kt — 7 @deprecated top-level

8. Redundant API
   MonitorState.updateSignalMetrics() is only a wrapper around
   refreshSignalMetrics(). One public name would be enough.

9. Duplicate settings bootstrap
   All repositories are loaded in both MonitorViewModel.init and

   loading only in the service and exposing via MonitorState) would simplify
   this.

ARCHITECTURE & CORRECTNESS NOTES
================================================================================

10. MonitorState synchronization is partial
    Recent screen-lock fix added monitorLock around main update paths, but:
    - shouldScheduleSearching2gAnnouncement(), format*Announcement() helpers read
      episode flags without the lock
    - NoSignalDebouncer itself is not thread-safe (only safe if all access goes
      through the lock)
    Worth either fully synchronizing announcement reads or moving episode state
    into an internal class guarded by one lock.

11. Foreground service type
    Service uses foregroundServiceType="dataSync". This app does cellular
    monitoring, audio, and telephony reads — not really data sync. On Android 14+,
    mismatched FGS types can cause throttling or kills in background. Worth
    reviewing specialUse (with declaration) or location given cell/telephony
    access.

12. Dual audio/voice instances
    GeigerCounterPlayer + CellVoiceAnnouncer exist in both MonitorViewModel
    (previews) and ConnectivityMonitorService (live monitoring). Previews are
    fine, but shared audio-focus handling could avoid edge cases if both were
    ever active.

13. formatNoSignalChange(stats) return type
    Overload is declared String? but delegates to a function returning String.
    Minor type cleanup.
